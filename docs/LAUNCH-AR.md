# من التطبيق إلى العمل الحقيقي — خطة الإطلاق

اكتب هذا الأمر في أي وقت ليخبرك النظام أين أنت بالضبط:

```bash
npm run preflight
```

يفحص إعداداتك وقاعدة بياناتك الحقيقية، ويصنّف كل بند إلى: جاهز، يحتاج مراجعة، أو مانع للإطلاق. ويطبع تحت كل مشكلة الأمر الذي يحلّها. هذا الملف يشرح ما وراء تلك القائمة.

---

## أولًا · ما هو جاهز فعلًا

هذه ليست واجهة عرض. الأجزاء التالية مكتملة ومُختبرة:

- **خوارزمية كشف الاحتيال**: ست إشارات موزونة بدرجة وتفسير لكل حساب.
- **خوارزمية المطابقة**: ثمانية عوامل وخطة محسّنة للميزانية.
- **الحسابات والأدوار**: تجزئة كلمات المرور، جلسات، قفل بعد المحاولات، عزل بيانات كل شركة.
- **غرفة العمليات**: اثنان وعشرون وكيلًا، مخفيّون تمامًا عن العملاء.
- **مولّد رسائل التواصل** بثلاث لغات من قوالبك.
- **مولّد العقود** الإندونيسي مع حساب الرسوم والضرائب.
- **الحماية**: ترويسات أمان، قائمة نطاقات مسموحة، تحديد معدّل الطلبات، ونسخ احتياطي دوري.
- **واحد وستون اختبارًا** تعمل في كل مرة.

## ثانيًا · ما هو تجريبي وعليك استبداله

كن صريحًا مع نفسك هنا، فهذه هي المسافة بينك وبين أول ريال:

| البند | الوضع | ماذا يعني |
|---|---|---|
| بيانات المؤثرين | **مولّدة** | مئة وعشرون ملفًا اصطناعيًا. لا يوجد مؤثر حقيقي واحد. |
| المدفوعات والضمان | **غير مربوطة** | العقد يحسب المبالغ، لكن لا مال يتحرّك. |
| التوقيع الإلكتروني | **غير مربوط** | زر يغيّر الحالة فقط. |
| قنوات الإرسال | **تحتاج ربطًا** | سير العمل جاهز، لكن بلا حسابات البريد والواتساب لن يُرسل شيء. |
| مصدر اكتشاف المؤثرين | **موضع مؤقت** | يحتاج مزوّد بيانات أو واجهات المنصات. |
| قاعدة البيانات | **ملف** | ممتازة لعشرات العمليات يوميًا، لا لآلاف. |

## المرحلة الأولى · أسبوع واحد: أغلق الموانع الثلاثة

**١. شغّل العقل.** ضع مفتاح كلود. بدونه الوكلاء لا يفكّرون، وهذا هو الفارق بين منصتك وأي جدول بيانات.

**٢. أغلق الحسابات التجريبية.** كلمات المرور المنشورة في الأدلة يعرفها كل من قرأها:

```bash
npm run user -- add you@yourdomain.com --name "اسمك" --role admin
npm run user -- delete admin@rabith.id
npm run user -- delete brand@rabith.id
npm run user -- delete creator@rabith.id
```

ثم فعّل إلزام تسجيل الدخول:

```bash
NODE_ENV=production
RABITH_AUTH_REQUIRED=1
```

**٣. ضع بيانات حقيقية.** امسح البيانات المولّدة وابدأ بمؤثرين تعرفهم أنت. أسرع طريق عملي: ابدأ بخمسين إلى مئة مؤثر جمعتهم يدويًا في مجالك (التجميل مثلًا)، وأدخلهم عبر الواجهة البرمجية:

```bash
curl -X POST http://localhost:8787/api/creators \
  -H 'content-type: application/json' \
  -H 'authorization: Bearer <رمز-جلستك>' \
  -d '{"handle":"@name","platform":"tiktok","followers":8200,"engagementRate":6.4,"avgViews":5100,"niche":["beauty"],"city":"Jakarta","priceIDR":{"post":300000,"video":800000}}'
```

درجة الاحتيال تُحسب تلقائيًا عند الإدخال. مئة ملف حقيقي أثمن من عشرة آلاف ملف مشكوك فيه.

## المرحلة الثانية · أسبوعان: اجعلها تعمل مع عميل واحد

الهدف ليس إطلاقًا عامًا، بل **حملة واحدة حقيقية من البداية للنهاية**.

**١. النشر على خادم.** أبسط مسار: خادم صغير مع نطاقك، وشهادة أمان، ثم:

```bash
docker compose up -d --build
```

اضبط هذه القيم:

```bash
RABITH_PUBLIC_URL=https://app.yourdomain.com
RABITH_TRUST_PROXY=1
RABITH_ALLOWED_ORIGINS=https://app.yourdomain.com
```

**٢. اربط قناة إرسال واحدة فقط.** البريد أولًا. وقبل أول رسالة، اضبط سجلات نطاقك للبريد:

```
SPF · DKIM · DMARC
```

هذه ليست تفصيلًا تقنيًا: بدونها تذهب رسائلك إلى مجلد المزعج، ويحترق نطاقك بعد مئة رسالة. أرسل عشرين رسالة في اليوم الأول، لا مئتين.

**٣. شغّل محرّك الأتمتة** واستورد سير العمل، واربط كلمة السر المشتركة. تابع أول تسلسل متابعة بعينك قبل أن تثق به.

**٤. أدر الحملة كاملة**: اكتشاف، فحص احتيال، مطابقة، عقد، تنفيذ، تقرير. اكتب في ورقة كل لحظة اضطررت فيها للخروج من المنصة وفعل شيء يدويًا. تلك القائمة هي خارطة التطوير الحقيقية، لا تخميناتك.

---

## المرحلة الثالثة · شهر: المال والالتزام

لا تقبض من عميل قبل هذين:

**١. المدفوعات والضمان.** اربط مزوّدًا إندونيسيًا:

```
Midtrans
```

أو

```
Xendit
```

القاعدة: لا تحتفظ بمال العميل في حسابك الشخصي. الضمان يحمي الطرفين ويحمي سمعتك، وهو أقوى حجة بيع عندك أصلًا.

**٢. التوقيع الإلكتروني.** اربط

```
PrivyID
```

ليصبح العقد مُلزِمًا قانونيًا بموجب قانون المعاملات الإلكترونية، لا مجرد ملف مطبوع.

**٣. الأوراق الرسمية.** كيان قانوني للفوترة، رقم ضريبي، واحتساب الضرائب المقتطعة في كل دفعة. المنصة تحسبها لك، لكن التوريد مسؤوليتك.

**٤. حماية البيانات.** أنت تخزّن بيانات أشخاص حقيقيين: أسماء، هواتف، أرقام حسابات. قانون حماية البيانات الإندونيسي يلزمك بسياسة خصوصية، وموافقة صريحة، وحدّ أدنى من البيانات المخزّنة، وحق الحذف. اكتب صفحة الخصوصية وشروط الاستخدام قبل أول تسجيل عام.

---

## المرحلة الرابعة · عند النمو

لا تفعل هذه الآن، لكن اعرف متى تفعلها:

- **قاعدة بيانات حقيقية**: انقل التخزين إلى

```
Postgres
```

عندما يكتب أكثر من شخص واحد طوال اليوم، أو تتجاوز البيانات بضعة آلاف من السجلات. طبقة التخزين معزولة في ملف واحد، فالنقل محدود الأثر.

- **مراقبة**: تتبّع الأخطاء وسجلّ مركزي وتنبيه عند توقّف الخدمة.
- **سقف تكلفة**: راقب استهلاك النموذج شهريًا. حدّ معدّل تشغيل الوكلاء مضبوط مسبقًا على ستين تشغيلًا لكل مستخدم في الساعة، عدّله حسب فاتورتك.
- **اكتشاف آلي للمؤثرين** عبر مزوّد بيانات، بدل الإدخال اليدوي.

---

## قائمة ما قبل الإطلاق

نفّذ الأمر، ولا تُطلق قبل أن تختفي كل العلامات المانعة:

```bash
npm test        # واحد وستون اختبارًا
npm run preflight
```

ثم اسأل نفسك ثلاثة أسئلة خارج الشاشة:

1. لو سجّل عميل الآن ودفع، هل يصل المال إلى حساب محمي؟
2. لو اختفى الخادم اليوم، هل أستعيد البيانات؟ (النسخ الاحتياطي يعمل تلقائيًا كل ست ساعات — تأكّد أنك تنسخها خارج الخادم أيضًا.)
3. لو طلب مؤثر حذف بياناته، هل أستطيع تنفيذ ذلك خلال يوم؟

إن كانت الإجابات نعم، فأنت جاهز لعميل حقيقي. ابدأ بواحد.
