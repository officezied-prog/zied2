# كيف تبني وكلاءك — دليل عملي

الوكيل عندنا ليس صندوقًا سحريًا. هو أربعة أشياء فقط: **هوية** (اسم ورمز ومجموعة)، و**تعليمات** تحدّد شخصيته ومهمته، و**أدوات** مسموح له باستعمالها، و**منسّق** يوزّع عليه العمل.

المنصة تأتي بواحد وعشرين وكيلًا جاهزًا. هذا الدليل يشرح كيف تشغّلهم، وكيف تصنع وكيلك أنت.

---

## المستوى الأول · شغّل العقل

بلا مفتاح، الوكلاء يعملون بقواعد ثابتة: يبحثون ويحسبون ويولّدون من القوالب، لكنهم لا «يفكّرون». هذا يكفي للعرض، ولا يكفي للعمل الحقيقي.

ضع المفتاح في ملف الإعدادات:

```bash
ANTHROPIC_API_KEY=sk-ant-...
CLAUDE_MODEL=claude-opus-5
CLAUDE_EFFORT=high
```

أعد التشغيل، وتأكد من السطر الثاني في رسالة البدء أنه يعرض اسم النموذج لا كلمة:

```
OFFLINE
```

قيمة العمق في السطر الثالث تتحكّم بعمق التفكير:

```
low · medium · high · xhigh · max
```

ابدأ بالقيمة المتوسطة للمهام الروتينية، وارفعها للمهام التي تحتاج حكمًا حقيقيًا مثل التفاوض والاستراتيجية.

---

## المستوى الثاني · اصنع وكيلك بملف واحد (بلا برمجة)

هذه الطريقة الموصى بها. أنشئ ملفًا في المسار:

```
config/agents.json
```

وضع فيه مصفوفة من الوكلاء. ابدأ من النسخة الجاهزة:

```bash
cp config/agents.example.json config/agents.json
```

### مثال كامل: وكيل التوافق الحلال

```json
[
  {
    "id": "halal",
    "glyph": "清",
    "group": "spec",
    "name": {
      "ar": "وكيل التوافق الحلال",
      "en": "Halal Compliance",
      "id": "Kepatuhan Halal"
    },
    "description": {
      "ar": "يراجع المنتجات والمحتوى من ناحية التوافق الحلال قبل إطلاق الحملة.",
      "en": "Reviews products and content for halal compliance.",
      "id": "Meninjau produk dan konten dari sisi kepatuhan halal."
    },
    "tools": ["get_brand", "get_campaign", "search_creators", "save_note"],
    "system": "أنت وكيل التوافق الحلال في رابط. لكل منتج أو حملة: تحقّق من حالة الشهادة، والمكوّنات التي تحتاج تدقيقًا (الجيلاتين، المذيبات الكحولية، الإنزيمات الحيوانية، القرمز)، وادّعاءات العبوة، ومدى ملاءمة أسلوب المؤثر لجمهور يهتم بالحلال. أجب بالشكل التالي: الحكم (سليم / يحتاج تحقّق / موقوف)، ثم البنود المطلوب التحقّق منها، ثم المستندات التي نطلبها من العلامة. وضّح دائمًا أنك لست جهة تصديق."
  }
]
```

### معنى كل حقل

| الحقل | ماذا يعني |
|---|---|
| `id` | معرّف فريد بحروف صغيرة. هو ما يناديه به المنسّق. |
| `glyph` | رمز واحد يظهر في الواجهة. اختر ما يعبّر عن الدور. |
| `group` | المجموعة، واحدة من: `core` `ops` `intel` `spec` `dev`. تحدّد اللون ومكان الظهور. |
| `name` · `description` | بثلاث لغات. إن كتبت نصًا واحدًا فقط، يُستعمل في اللغات الثلاث. |
| `tools` | الأدوات المسموح بها فقط. الوكيل لا يستطيع تجاوزها. |
| `system` | التعليمات: من هو، ماذا يفعل، بأي ترتيب، وبأي شكل يجيب. |

### تعديل وكيل موجود بدل إنشاء جديد

إذا استعملت معرّفًا موجودًا، تُستبدل الحقول التي كتبتها فقط ويبقى الباقي كما هو. مفيد جدًا لتغيير أسلوب وكيل المبيعات دون لمس الكود:

```json
[
  {
    "id": "sales",
    "system": "أنت وكيل المبيعات في رابط. اكتب رسائل قصيرة ودافئة وملموسة، لا تتجاوز مئة وعشر كلمات. ابدأ بملاحظة محدّدة عن حملة العلامة الأخيرة. اعرض دائمًا حملة تجريبية واحدة مدفوعة بمؤشّر أداء متّفق عليه، ولا تتابع أكثر من مرتين."
  }
]
```

### تحقّق أن وكيلك حُمّل

أعد تشغيل الخادم، واقرأ سطر الوكلاء في رسالة البدء:

```
Agents      → 22 total (2 from config/agents.json)
```

وإذا كان في ملفك خطأ، يُطبع الخطأ ويُتجاهل ذلك الوكيل وحده — لا يتوقف النظام أبدًا. جرّب أيضًا:

```bash
curl -s localhost:8787/api/agents | grep halal
```

ثم افتح صفحة الوكلاء في التطبيق: سيظهر وكيلك في مجموعته، وتستطيع مخاطبته مباشرة.

## الأدوات المتاحة

الأداة هي ما يجعل الوكيل فاعلًا لا ثرثارًا. هذه كل الأدوات الحالية:

| الأداة | ماذا تفعل |
|---|---|
| `search_creators` | بحث في قاعدة المؤثرين بفلاتر دقيقة |
| `match_campaign` | تشغيل خوارزمية المطابقة وإرجاع خطة ضمن الميزانية |
| `fraud_audit` | تفسير إشارات الاحتيال لحسابات محدّدة |
| `get_brand` · `list_brands` · `update_brand` | قراءة وتعديل سجلّات الشركات |
| `get_campaign` | قراءة حملة بكل نتائجها |
| `generate_outreach` · `save_outreach` | توليد رسالة من القوالب وحفظها كمسودة |
| `generate_social_post` | إنشاء منشور مجدول لصفحة |
| `trigger_n8n` | إطلاق سير عمل خارجي: إرسال، نشر، إشعار |
| `save_note` | تدوين ملاحظة على شركة أو حملة |
| `platform_stats` | إحصاءات المنصة كاملة |
| `delegate` | خاص بالمنسّق: يفوّض مهمة فرعية لوكيل متخصص |

**قاعدة مهمة:** أي أثر خارجي (إرسال بريد، نشر منشور) يمرّ عبر الأداة الأخيرة المذكورة في محرّك الأتمتة، لا مباشرة. هكذا يبقى لك قرار الموافقة، ويبقى كل إرسال مسجّلًا.

## كيف يعمل المنسّق

المنسّق هو الوكيل الوحيد الذي يخاطبه المستخدم. دورته ثلاث خطوات: يخطّط، ينفّذ، يراجع.

1. يقرأ الطلب ويحدّد الوكلاء المطلوبين.
2. يفوّضهم **بالتوازي** عندما تكون المهام مستقلّة.
3. يوفّق بين النتائج، ويغلّب رأي وكلاء الاحتيال والقانون والمالية على حماس وكلاء النمو.
4. يسلّم إجابة واحدة موحّدة مع قائمة خطوات تالية.

عمق التفويض محدود بمستويين، حتى لا يدخل الوكلاء في حلقة لا تنتهي. وكل وكيل جديد تضيفه يظهر تلقائيًا في قائمة المنسّق، فيستطيع تفويضه بلا أي تعديل إضافي.

---

## كيف تكتب تعليمات وكيل جيدة

هذه أهم خمسين سطرًا في المشروع كله. القواعد التي تعمل فعلًا:

**١. حدّد الدور والحدود في أول جملة.** «أنت وكيل التفاوض في رابط» أفضل من «أنت مساعد ذكي».

**٢. اطلب ترتيبًا لا موضوعًا.** بدل «تحدّث عن الأسعار»، اكتب: «أولًا احسب متوسط التكلفة لكل ألف مشاهدة، ثم اقترح نطاقًا عادلًا، ثم اكتب رسالة التفاوض».

**٣. حدّد شكل الإجابة.** جدول؟ حكم من ثلاث كلمات؟ ثلاث نقاط؟ الوكيل الذي لا يعرف شكل مخرجاته يعطي مقالًا.

**٤. اذكر ما لا يفعله.** «لا تدّعي أن الرسالة أُرسلت ما لم تؤكّد الأداة ذلك» و«لست بديلًا عن محامٍ مرخّص» جملتان توفّران مشاكل حقيقية.

**٥. اربطه بالواقع المحلّي.** العملة بالروبية، الضرائب، المواسم، القوانين الإندونيسية. التفاصيل المحلّية هي ما يجعل الإجابة قابلة للاستعمال.

**٦. اطلب منه أن يقول «لا أعرف».** الوكيل الذي يخمّن أرقام المؤثرين أسوأ من وكيل صامت.

## المستوى الثالث · أداة جديدة بالكود

إن احتاج وكيلك قدرة غير موجودة (مثل: اقرأ مبيعات من متجر)، أضف أداة:

**١. عرّف شكلها** في الملف:

```
apps/api/src/agents/tools.js
```

داخل الكائن:

```
TOOL_DEFS
```

بالاسم والوصف ومخطّط المدخلات.

**٢. اكتب تنفيذها** في الدالة:

```
execute()
```

في الملف نفسه، وأعد كائنًا صغيرًا ومفهومًا — لا صفحات من البيانات الخام.

**٣. امنحها للوكيل** بإضافة اسمها في حقل الأدوات داخل ملف الإعدادات.

الوصف الذي تكتبه للأداة هو ما يقرأه النموذج ليقرّر متى يستعملها، فاكتبه بعناية: ماذا تفعل، ماذا ترجع، ومتى لا تُستعمل.

## الاختبار

بعد أي تعديل:

```bash
npm test
```

ثم جرّب وكيلك مباشرة:

```bash
curl -s -X POST localhost:8787/api/agent/run \
  -H 'content-type: application/json' \
  -d '{"agent":"halal","message":"راجع منتج السيروم قبل الحملة","context":{"lang":"ar"}}'
```

الإجابة تحتوي على الخطة، وكل استدعاء أداة بمدخلاته ومخرجاته وزمنه، والنص النهائي. هذه أسرع طريقة لمعرفة لماذا تصرّف الوكيل كما تصرّف.

---

## ترتيب العمل الموصى به

1. شغّل المفتاح وجرّب المنسّق بأسئلة حقيقية من عملك.
2. اقرأ خط زمن الاستدعاءات: أين أخطأ الوكلاء؟
3. عدّل تعليمات الوكيل الضعيف من ملف الإعدادات، لا من الكود.
4. أضف وكيلًا جديدًا فقط عندما تجد مهمة متكرّرة لا يغطّيها أحد.
5. أضف أداة جديدة فقط عندما تكون المعلومة خارج المنصة.

القاعدة العملية: **وكلاء أقل بتعليمات أدقّ أفضل من عشرين وكيلًا سطحيًا.**
